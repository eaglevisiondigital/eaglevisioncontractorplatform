# Cycle 11 · service continuity

`ServiceContinuity({sources, enabled = false, onSelectJob?})` is an isolated local
staff navigation surface over the same actual OperatingSources repositories. Main
owns mounting, shared contracts and combined browser/accessibility evidence. No
service request, property, estimate, job, report, financial record or store is created.

## Actual request → issued job → documentation → Passport

`readServiceContinuity(sources, {query, location_id, job_id}, gate)` composes the
existing C10 ServiceDesk and C9 PortfolioService readers. Four prepared job handles
retain three actual requests and three properties. Two jobs on one property keep
distinct job, issued estimate/version, original offer/LOCAL-TEST receipt and exact
published report/version identities. A request-to-estimate association is explicitly
staff-selected; the UI never claims a recorded request/estimate foreign key or a
genuine customer approval.

Literal search covers allowed request/source labels and exact IDs. Property/job
filters combine with accurate matching counts while available coverage stays visible.
A foreign filter or conflicting property/job is denied rather than replaced. The
breadcrumb connects existing service records, one exact issued job, recorded
completion documentation and its property's available Passport history.

`openServiceContinuityJob(view, jobId)` admits an exact visible original job only.
The staff request/receipt block stays separate from the `customer_safe` projection.
That allowlist contains contractor identity/palette, property reference, issued
customer-facing scope, distinct job/version references and published reports with
checklist/observation/recommendation evidence. It excludes internal costs, suppliers,
workforce, rates, margins, payroll, private notes, staff identity and receipt metadata.

`openServiceContinuityReport(detail, exactReference)` re-reads the same authorized
property/report/published version through the existing Passport evidence reader.
There is no latest-report or fuzzy fallback. Exact recorded report/job links are
labeled; ambiguous links remain UNKNOWN. Property documentation is never silently
assigned to the selected job. `selectServiceContinuityJob(detail)` separately checks
current sources before providing the exact local navigation callback target.
