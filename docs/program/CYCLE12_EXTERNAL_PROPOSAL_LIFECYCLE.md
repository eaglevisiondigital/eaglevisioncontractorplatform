# Cycle12 · controlled external proposal lifecycle

`ExternalProposalLifecycle({sources, enabled = false, onSelectJob?})` is one bounded
local staff review panel over the same actual `OperatingSources` environment. It
extends the existing Cycle11 Sync Admission and Cycle10 Advanced Handoffs in all
seven modes: offline, voice, receptionist, accounting, procurement, Storm/Network
and trade. It introduces no integration engine, synchronization store, parser,
provider, customer packet or canonical business record. Main owns the optional
mount, shared registry, source indexes and actual combined browser evidence.

## Original source and immutable comparison

`readExternalProposalSource(sources, handoffInput, gate)` delegates to the original
`readSyncAdmissionSource`. `externalProposalReferences(source)` projects the same
eight existing exact source fields plus actual plan ID/revision, scheduled visit
ID/revision and published visit ID/revision. Only an explicit UI action copies these
as a human proposal; there is no automatic import, external document or identity
resolution by wording.

`reviewExternalProposalLifecycle(source, {proposal, workflow,
review_expires_at_ms}, syntheticClock)` delegates its source comparison to the
original `reviewSyncAdmission`, preserving that immutable comparison/hash and its
original multi-target label claims. Separate per-field workflow differences show
MATCH, MISSING or CONFLICT against the actual recorded revisions. Missing, foreign,
conflicting and multi-target references remain quarantined. No later label, deadline,
source container, view or clock object replaces that retained lifecycle comparison.
Source and workflow revisions are not inferred from a note, latest-version lookup,
property wording or another job at the same property.

One ephemeral control fence per original estimate repository/company/job/mode is
reserved before the first comparison await. It retains original inputs, comparison,
clock, terminal status and immutable control-event snapshots only. This is local
review custody, not business ownership, an operational lifecycle table, transaction
ledger or durable command store. Prior comparison/evidence and earlier control-state
snapshots remain unchanged when later local control events are observed.

## Fixed expiry, cancellation and revocation

The reviewer supplies a fixed deadline after explicitly supplied synthetic now and
within24 hours. The UI requires **I set this local review expiry against the synthetic
clock.** Deadline fields lock after initial review; a separate **Apply synthetic review
time** action advances the observed manual time. There is no timer, automatic clock,
background execution or genuine operational expiry guarantee. The supplied clock is
explicit trusted test input, never a substitute for server time or real authorization.
Clock rollback yields terminal UNKNOWN; reaching the deadline yields EXPIRED and
never grants renewal authority.

`cancelExternalProposal` and `revokeExternalProposal` require an exact retained
lifecycle/hash and explicit confirmation. They withdraw local review authority;
they do not undo business records, revoke genuine Auth or reset an original engine
hold. Cancellation/revocation during a pending delegation is checked after awaits
and withholds the result. Missing/conflicting source evidence stays quarantined in
the unchanged original comparison regardless of later local status labels.

`externalProposalState(view)` checks current evidence at render and exposes immutable
local control events. Terminal UNKNOWN never becomes current after restoring an input,
gate or clock. `inspectExternalProposalLifecycle(view)` may inspect only the retained
original C11 handoff; no replacement or replay exists. A new view, refreshed component,
source container or external label cannot reset this same-tab fence. A full runtime
reload loses these disposable sources and custody; no cross-reload durability or
operational authority is claimed.

## Separately confirmed original delegation

`prepareExternalProposalHandoff(view, {confirmed,
reviewed_lifecycle_sha256})` requires an unexpired exact retained comparison and
separate explicit current staff confirmation. It calls the original
`prepareSyncReviewHandoff`, which calls the original `prepareAdvancedHandoff` and
original mode engine. C11/C10 and canonical one-use holds remain authoritative;
competing preparation or lost acknowledgment cannot be bypassed through this panel.
The immutable evidence retains the actual original C11 handoff object and hashes,
without reconstructing its engine result or creating new domain records.

Final-await checks cover the original source/root/repository/model/context, original
proposal/deadline, current eligible synthetic staff, gate, monotonic synthetic time
and original delegation confirmation. Changed context immediately withholds old
presentation and withdraws in-flight results. Copied objects cannot recover retained
bindings. Accessors, serializers, coercive input and extra fields are denied without
executing them. DEV/explicit enablement/HTTP-loopback UI admission precedes source
getters; domain source reads require enabled/confirmed admission first.

Original gaps persist in every mode. Offline remains session-only with UNKNOWN
availability and no authenticated sync. Voice reviews literal typed text with no
recognition, microphone or model; no new voice parsing is added. Accounting lacks
operational invoice/contract mapping. Procurement cannot manufacture catalog links,
supplier bids or orders. Receptionist consent/suppression/recipient/sender remain
unverified and no recipient/callback/provider resolves. Storm/Network cannot infer
incident dates, physical conditions or partner vetting. Trade context changes no
brand, license, code compliance or physical completion authority. Every execution
capability remains false.
