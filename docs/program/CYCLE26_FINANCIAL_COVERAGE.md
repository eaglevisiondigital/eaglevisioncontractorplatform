showed that reloading unchanged native sources erased the operator's exact selected
ID and literal query, despite no source change. This required the same manual entry
again. The original confirmation was already cleared; that behavior is preserved.
The transient loopback-only fixture used the actual component and original disposable
repository preparer, then closed its browser and server. No product route was added.

only when both original reads are current and the native cost comparison proves the
same canonical repository, job, customer, property and source. It clears the previous
verification and confirmation immediately, before awaiting the refresh. Staff must
explicitly verify and confirm again. Stale prior reads, changed source facts, unknown
holds, missing IDs and foreign/sibling sources never rebind to a current/latest row.
The retained key and regenerated current-revision input are presentation context;
they are not an inspection, approval, receipt or renewed command capability.

The small validator remains in the existing cost-action source. It reuses original
read/current guards, the original saved-cost comparison and exact original action
validation. There is no new reader owner, projection layer, map, store, ledger,
calculator, command custody or navigation engine. Canonical categories, recorded
actual/committed/remaining costs, profitability and independent invoice requirements
continue to use original amounts and original events. Durable receipts and provider
settlement remain UNVERIFIED; no posting, invoice issue, debt or payment is authorized.
Scoped CSS, including the independently verified contrast correction, is unchanged.
