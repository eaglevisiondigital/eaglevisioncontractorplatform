# Cycle14 · direct service source continuity

`ServiceSourceContinuity({sources, enabled = false, selectedJobId?, onSelectJob?})`
continues an Operating Center job into its actual service request, immutable issued
scope and the property's existing exact published report/Passport sources. Main may
prefill the retained authorized job; explicit **Inspect selected service source**
reads it once. A foreign selected ID denies rather than falling back to another job.
This is a separate bounded customer-continuity package, not another requirements
report, customer workflow, history store or completion engine.

`codex/program-cycle-fourteen`. Five NEW files only. Main owns mounting, Operating

## Original request → issued scope → report/version → Passport finding

`readServiceSourceContinuity(sources, {job_id}, gate)` composes the existing C13
`readServicePassportDesk` and `openServicePassportJob`. It preserves the actual
request ID, summary and recorded state, exact customer/property/job/estimate/issued
version and original customer-safe scope/Passport projection. A request-to-scope link
remains staff-selected; no recorded request/estimate foreign key or genuine customer
acceptance is manufactured. A sibling job at the same property retains its own issued
version and documentation relationship.

The original C13 customer-safe projection is reused directly. Published report/version
references and selected-job associations remain unchanged. Property documentation
whose exact job relationship is absent, ambiguous or for a sibling stays UNKNOWN
for the selected job. Available report counts never claim complete history, verified
work coverage or physical completion. The same published version is retained even
when later documentation records no new findings.

`openServiceSourceReport(read, exactReference)` delegates to the existing
`openServicePassportReport` reader and returns the original safe report content.
The UI displays exact report/version/property, recorded visit/publication dates,
summary, recorded checklist marks and separate observations/recommendations.
There is no newest/nearest/label-based fallback, generated report, new publication
or second content engine. `openServiceSourceFinding` delegates to the original exact
published finding ID/source-position reader. Source/report/finding headings receive
focus. **Back to published report selection** retains the same original source and
property context. **Open continuity existing job …** is a separate current exact
navigation action after report inspection.

No new customer/request/job/history record, saved preference, lifecycle stage,
verification, approval, attestation or durable state is introduced. React selection
and read bindings are ephemeral navigation metadata only. Existing published and
issued objects remain authoritative and immutable.

## Access, uncertainty and presentation

The component defaults OFF. DEV, explicit flag and literal HTTP loopback checks
precede source getters, input coercion and serialization. Strict own-data bounded
job input and original report/finding references exclude accessors, serializers,
foreign sources and reconstructed view authority. Original source root/repository/
model identity, eligible current staff, gate, selected job and all existing
customer/property/issued-version/report/workflow checks run after awaits, after the
final digest, on render and before navigation.

Changed selection immediately withholds old content and discards late responses.
Observed source/access/reference drift or lost read acknowledgement makes the
retained navigation terminal UNKNOWN. Restoring fields cannot revive it, supply a
replacement ID or replay a command. No command exists in this read-only package.
The original snapshot remains immutable and current-state uncertainty stays outside
it. Same-tab evidence is not genuine Auth or durable custody.

costs/rates, suppliers, workforce/receipt metadata and other customers. Actual request
review stays separate from customer-safe content. Physical completion, customer
acceptance and warranty remain UNKNOWN. After-phase reports, checkmarks, photos or
absence of findings never become physical PASS, repair, approval or financial rights.
