# Cycle 10 · source-safe follow-up admission

This additive, default-OFF package extends the existing multi-job maintenance desk.
`FollowUpAdmission` accepts the same `OperatingSources` and optional exact-job callback.
Main owns mounting and combined browser evidence. There is no new consent,
maintenance, customer, message or scheduling store.

## Two explicit staff review steps

`readFollowUpDesk` loads exact existing recurrence occurrences and published finding
sources through `readPortfolioMaintenance`. Staff search and inspect the source-bound
window, customer/property/job, plan/revision and recorded due date. Counts describe
available admitted records, never complete history or physical completion.

After selecting an exact displayed occurrence, staff choose an unsaved proposed date,
follow-up/renewal planning kind and explicit communication purpose, then separately
confirm `prepareFollowUpAdmission`. The factual due date and source selection remain
immutable. No enrollment, renewal terms, visit, customer obligation or message is
created. A missing or denied historical channel preference never becomes permission.

## Final admission is always blocked

Preparation composes the existing portfolio consent-preflight reader, then re-reads
`readGrowthReminderReview` for the exact source customer/property. After hashing it
reads the canonical contact/recurrence evidence again and compares it before returning.
Every await is followed by original live input, source handle, eligible membership
and company/customer/property/job checks. Withdrawal or conflicting evidence fails
closed. The existing reader has no authoritative purpose-specific suppression,
enrollment, sender or atomic send gate; these fields stay UNVERIFIED and the actual
send gate is explicitly ABSENT. No missing record is represented as clear consent.

The immutable allowlisted staff packet includes exact source identities, factual due
date, unsaved proposed date/purpose, safe historical contact-v1 state/reference,
source/consent hashes, missing requirements and SHA-256 integrity. It excludes contact
addresses/numbers, private contractor notes, supplier/payroll/cost information and
unrelated records. Recipient and provider request remain null; all authority flags
are false. Historical observations never become current communication authorization.

## One-use local review and uncertainty

Before the first preparation await, a private in-memory hold binds the actual shared
property repository and exact company/customer/property/occurrence source. Concurrent
staff actions, a new desk/container, changed date/purpose/channel or copied view
cannot replace that attempt. Failures retain UNKNOWN; only exact retained read-only
reconciliation is available, without replay or a new ID. Frozen packets do not change
when sources or proposed inputs change. Browser memory and integrity hashes do not
establish durable custody, real Auth or an atomic consent-at-send transaction.

`openFollowUpSource` navigates the existing exact source reader. Current source/model
replacement with the same IDs withholds prior presentation. Proposed date changes
clear confirmation and prior output. Scoped premium styling keeps named regions,
visible labels, focus destinations, 44px controls, source wrapping and mobile stacking;
approved portals, global styles and artwork remain unchanged.

Focused tests cover three brands, actual consent withdrawal, missing suppression,
strict primitives, source/customer/property/member denial, final-await races,
concurrent/duplicate/new-container holds, lost-read UNKNOWN, immutable packets,
source navigation, privacy and no messages or business writes. Main independently
reviews composition and desktop/tablet/mobile/accessibility behavior.

All migrations, customer14/4B, P1/frozen artifacts/approvals, Netlify/executor,
recovery/MFA/NMI/Auth/provider/financial/communications/hosted/deploy/merge gates stay
unchanged. Release 1.0 remains NOT READY / NOT AUTHORIZED.
