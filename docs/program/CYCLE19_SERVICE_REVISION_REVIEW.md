## Existing authority and exact lineage

- `PropertyRepository.read` supplies current published/visit/plan identities.
  Existing `revise` → `saveVisit` → `submit` → `publish` keeps the same visit and
  appends a new report UUID with an incremented per-visit published version. All
  writers occur only in source-based tests or Main's separately owned exercise.
- `createPropertyPassportJobHistory` and `readPropertyPassportEvidence` supply
  strict customer-safe issued scope and report/finding/checklist projections.
  Report ownership follows exact organization/customer/property plus recorded
  report→visit→plan→job, never dates, names or similar descriptions.
- `customerModel.compareReports` reuses the original comparison/attention engine.
  Only its safe checklist result differences, finding difference flags and
  uncertainty text enter this view. Its repair-scope pricing is excluded.
- Main's `readSavedRevision`, source/access fences, comparison and opaque selection
  CAS own the shared read protocol. No second business store or revision engine.

Every previously observed published version is checked against actual current raw
published content AND the original safe Passport projection. The original ID,
version, visit, plan, owner, summary, dates, phase, visible findings and checklist
must remain identical. Per-report SHA-256 binds the safe content and visit/plan
lineage. Missing, rewritten or ambiguous history cannot be accepted as a new revision.
The immutable issued-source pin alone is insufficient; this package checks both.

Known saved updates can stale the old mutable capture while fresh exact access
still permits inspection of historical evidence. Observed access, immutable-history
or ownership failures retain canonical Operations/company/job UNKNOWN across fresh
wrappers and restored data. That metadata is not a durable business record or Auth.
A raced candidate must be read and inspected again. New reads and adoption never
revive an original stale control, renew an attempt, clear UNKNOWN or call
`prepareCompletionReview`. Its original once-per-job claim remains authoritative.

## API and working consumer

`ServiceRevisionReview(SavedRevisionPanelProps)` uses the same `sources`, default
`enabled=false` and independently checked `selectedJobId`. Other original optional
presentation callbacks are accepted but never called by adoption. DEV, explicit
flag and literal HTTP loopback admission precede source descriptors/serialization.
No hinted job fallback. Without a hint, the existing SharedRecordSearch selects an
available exact job; there is no new job directory.

Domain exports:

- `readServiceRevisionReview(sources, jobId, gate)` captures the original exact
  report from the retained job handle, all recorded job reports and safe scope.
- `readServiceRevisionUpdates(before)` explicitly reads the latest unique published
  sibling in the selected report's same visit and plan. It does not adopt it.
- `inspectServiceRevisionComparison(before, current)` invokes the original
  comparator and returns an opaque retained adoption inspection.
- `createServiceRevisionSelection`, `readServiceRevisionSelection` and
  `adoptServiceRevisionReview(selection, inspection, expectedGeneration, confirmed)`
  compose Main's opaque CAS. No copied inspection, duplicate or competing stale
  generation can adopt. Repeated explicit adoption advances the same selection.
- `assertServiceRevisionAccess`, `assertServiceRevisionCurrent`,
  `filterServiceRevisionReports` and `inspectServiceRevisionReport` retain exact
  source checks, bounded literal filters and old-version access.

Stable controls and demo:

1. In the existing default-off saved-revision slot, retain an authorized selected
   job and choose **Read published service source**.
2. Use Main's separately confirmed existing-canonical-method exercise to revise and
   publish that original visit. No author writer exists.
3. Choose **Read saved service updates**, then **Inspect published revision
   comparison**. Both exact report IDs/versions, summaries and same-visit provenance
   remain visible. The selected source is unchanged.
4. Check **I reviewed both exact published versions.** and choose **Adopt inspected
   published version**. The local generation advances; no callback or command runs.
5. **Inspect service version 1** remains available with its exact report ID;
   **Return to selected service version** restores the adopted source. Search text
   and recorded-phase filters persist through reading and adoption.
