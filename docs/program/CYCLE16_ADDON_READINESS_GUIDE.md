## Source and API contract

- `readAddonReadinessJobs(sources, gate)` returns the original finite
  `OperatingSelectionView`, with retained-source checks. Available handles are not
  complete company history. `selectAddonReadinessJob(view, selectedJobId?)` rejects
  invalid/foreign/ambiguous hints without fallback. Selection never grants access.
- `filterAddonReadinessJobs(view, {query, location_id})` intersects literal search
  and an exact admitted property. Same-property jobs stay distinct. Filters never
  create a customer/job/request relationship or resolve an absent source.
- `readAddonReadinessGuide(sources, {job_id, kind, edition}, gate)` delegates to
  original `readAddonTaskContinuity` and returns the SAME original task object.
  Modes and labels come from `advancedHandoffKinds` and `addonReviewModes`: offline,
  voice, receptionist, storm_network, accounting, procurement and trade. Editions
  come from the existing `tradeEditions`; human context never changes company industry.
- `openAddonReadinessControls(task)` and `resumeAddonReadinessControls(task)` return
  the SAME original frozen `{sources, selection}` props. `returnAddonReadinessContext`
  returns the original immutable job/mode/edition/issued/source-hash context.
- `filterAddonReadinessRequirements(task, query)` searches the original requirement
  text literally. `filterAddonReadinessReferences(task, query)` searches the original
  typed issued/report/plan/visit/time/material references without substitution.
- `inspectAddonReadinessReference(task, reference)` delegates to original
  `inspectAddonReviewReference`, then checks the exact retained task again after the
  final await. It returns that original source-reference result, not a new record.
- `assertAddonReadinessJobsCurrent` and `assertAddonReadinessCurrent` fence original
  root/company/member/model/repository/job/issued/source revision/input/gate identity.
  Copies, changed inputs or observed stale evidence cannot revive the retained view.
- `navigateAddonReadinessJob(task, reference, expectedCallback, live)` re-inspects
  that exact original reference before calling the same job's host callback.
  `live` has own data `{current: callback | undefined, generation: number}`. The
  expected function and callback generation must agree before/after the final await.
  Getters reject without invocation. Removal/replacement/restoration never calls an
  obsolete or replacement callback from an older navigation.

The React wrapper updates the callback slot in a layout effect and increments its
local generation on callback change/cleanup. Callback changes are absent from source
keys and do not remount the guide or original controls. Async navigation cancellation
keeps original control state intact. Source/hint withdrawal invalidates pending reads
through the original gate and source fences. The callback selects an existing job;
no inferred mode-to-business-action mapping or operational capability is created.

## Working controls and return

Stable region/title: **Add-on readiness guide**. With Main's explicit local guide
admission, the selected-job hint preselects one independently checked actual source.

1. Use **Search add-on jobs** and **Add-on property**. The **Add-on source job**,
   **Add-on source mode** and **Add-on review edition** selectors choose the context
   once. Select **Inspect add-on readiness source**; this reads only, with no review
   or proposal started automatically.
2. Review the exact tenant/customer/property/job/issued/saved revision/report/version
   and source hash, original catalog-link state and missing requirements. **Search
   add-on requirements** filters only those original texts; no matches never means
   readiness. **Missing provider and operational evidence** preserves original
   UNKNOWN/NONE labels for provider/sync/voice/bid/accounting/incident/network/
   availability/physical-completion evidence.
3. Use **Search add-on references**, then **Inspect exact add-on reference [kind]
   [id]**. Source-heading focus moves to exact kind/ID/version/job/issued evidence.
   A separate **Open same add-on job [label]** rechecks source and live callback
   after its final inspection await; host navigation may unmount local presentation.
4. The original component appears below with no second job/mode/source-copy form.
   Its original **Bound review label**, **Synthetic review expiry UTC** and explicit
   fixed-expiry confirmation precede **Review pinned source**. Subsequent original
   confirmation/actions remain unchanged. The guide never calls those actions.
5. **Return to add-on source context** hides the same original control using
   visibility only. **Resume retained original add-on review** restores that SAME
   mounted instance, entered label/time/expiry, confirmations, result and hold.
   Filters/reference selection also remain retained. Once inspected, context selectors
   stay locked; returning does not offer a fresh mode, source, deadline or label bypass.

Original lifecycle state cannot be inferred by source inspection and remains visibly
separate. The original control owns REVIEWED/PREPARED/UNKNOWN/expired/cancelled/revoked
states. A fresh read cannot bypass its original one-use key. No new window or ID is
created by Return/Resume, search or source inspection. Same-tab memory is not genuine
Auth, durable custody or operational acceptance.
