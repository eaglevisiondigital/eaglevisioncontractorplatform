## Working source path

The operator retains an exact job through the existing workbench. **Review exact
request and report sources** explicitly selects that staff context and loads the
original guide and property readers. The request's exact recorded summary/status
appear beside the original issued job/estimate/version, report ID/version, visit,
plan and job IDs. All relationships use original foreign keys and exact identifiers.

Request-to-job remains `UNKNOWN_ABSENT_FROM_CURRENT_SOURCE_CONTRACT`: the original
source contract has no such recorded FK. A retained intake selector and explicit
staff selection are not proof that a request originated a job. Property, date,
similar descriptions and finding labels never supply the missing relationship.

**Inspect source chain** first requires the exact original report reference to
belong to this job's C22 history. It then calls the unchanged
`openServiceCompletionReport`. Same-property reports from other jobs, copied
references and mixed customer/property handles are denied. The original scope,
source IDs, completion requirements, unavailable media and missing scope-line
documentation matching remain visible. Physical completion, customer acceptance,
warranty, full history and delivery are never inferred.

The original C22 panel remains below an explicit disclosure, unchanged, with its
original report renderer, filters, refresh and same-property job callback. No
second navigation system or replacement form is introduced. Main owns the existing
opt-in renderer selection and disposable source environment.
