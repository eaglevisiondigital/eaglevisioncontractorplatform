# V1 Finance and Owner source integration

This is a two-file test and evidence package from exact Finance draft #294,
`e733774533bb4aab0a30782855aeb367c72089d0`. Runtime, source-admission helpers,
historical evidence, protected designs, configuration and dependencies are unchanged.
The reviewed Finance source retains both leading checks and the two final checks
for historical access and current-source freshness. This package adds no business
engine, data store, financial writer, navigation owner or operational capability.

The new suite declares six cases for each of the three approved contractor brands:

- Actual original synthetic membership revocation during Finance filter capture
  prevents private cost rows and separately inspected Owner navigation. Native
  membership mutation is checked directly; it is not genuine hosted Auth evidence.
- Withdrawal of the earlier Finance review admission prevents historical output
  while the separately admitted current Finance and Owner reads remain valid.
  A local confirmation is distinct from native membership authorization.
- Actual recorded material and reviewed time changes invalidate old current reads.
  Fresh Finance and Owner reads use the same original job, expense, review and time
  identifiers, canonical integer facts and independent invoice requirements.
  Approved unposted time remains UNKNOWN cost coverage, absent locked-labor
  evidence and no invoice issuance. Filtering does not adopt a saved selection.
- A second job on the same property, a different company and copied handles cannot
  substitute for an original Finance or Owner source or select another destination.
- A later canonical forecast invalidates retained cost rows and inspected Owner
  navigation. UNKNOWN forbids replay; toggling a presentation confirmation does not
  revive the stale source or advance the saved-selection generation.
- Default-OFF readers reject before any unadmitted source handle is captured.

The setup reuses `prepareCorrectionPreviewSources`, which extends the existing
`prepareOperatingSources` environment. Existing native fixture operations create
the time and expense evidence; no alternate restoration or business-state layer is
introduced. Shared identity includes organization, actor, customer, property,
estimate, issued version and exact job. The second same-property job remains
distinct. Owner ordering, source facts and task navigation come from the original
readers. Tests spy on original financial, property, release and network writers
after explicit fixture changes to verify that reviews invoke none of them.

Recorded timestamps use a nonoverlapping UTC interval after the fixture's available
time entries. The Owner review uses its original source day and timezone. No
wall-clock urgency, work availability, paid-labor policy or completion is inferred.

Only `tests/cycle33-v1-finance-owner-integration.test.ts` is executed, with one
worker, retry zero, and the original Vite test and hook budgets of 30 seconds.
This is additional coverage of already reviewed source, so no runtime correction
or parent-RED claim is made. The execution is a test-only author worktree based on
the exact published source, rather than a clean committed-candidate capture.
The first complete run passed all 18 cases with zero failures, skipped cases or
todos in 149.370 seconds on local Node 24.20.0. Its raw native report SHA-256 is
`7b9caf8f07467095280a57008308035ddedf1f108ee6b0e6255d3f58894fdcbc`.
The final private freeze records the source hashes and scoped quality outcomes.
No prior successful cohort or browser suite is rerun by this package.

This suite does not repair or relabel draft #294's historical C19 source-preflight
failure. Its new finite successor admission remains Main-owned, separately
reviewable work; old source hashes and immutable manifests are preserved.
No new-head hosted, transitive-source, browser accessibility, visual approval,

All eleven operational D1 owner roles remain unassigned. P1, customer14/4B, NMI,
recovery, provider, financial, communication, dispatch, database, deployment and
