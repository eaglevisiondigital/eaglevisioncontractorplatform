The default-OFF `VerifiedOperatingSuggestions` reads actual C11 Daily Action Center
cards, which already compose C10 Priority Explanations and C9 Business Briefing
through the current canonical Finance/Field/issued/report readers. Existing card
keys, rank, recorded facts, recommendation, source IDs, target, version/revision,
criteria and original missing evidence remain authoritative. This package adds
source-specific recorded-state comparisons, not a Copilot engine or autonomous
suggestion generator. No model/provider or preparation command is called.

Facts, staff-selected ordering/day/timezone, manual next review and blocked action
authority remain separate. `MATCHED_RECORDED_STATE` means only that the exact local
recorded state was recognized and matched. It never means authorized action,
physical completion, urgency, real authentication or successful financial execution.
Unknown, missing, unrecognized and ambiguous state stays UNKNOWN. All action
permissions are false, including when every required source check matches.

Required checks are specific to the existing source type:

- Finance checks the exact existing job/revision/issued/expense references and the
  original canonical cost-coverage classification and invoice-readiness status.
  NO_GO stays NO_GO. No ledger verification/export is duplicated and no Cycle12
  Finance file is imported. Capture/refund/paid/settled outcomes remain UNKNOWN.
- Visits check exact visit revision/date, explicit plan/job/customer/property link,
  recognized recorded status/phase and plan revision/recurrence definition. The
  plan has no canonical operational activation status; date-only evidence supplies
  no appointment window, live capacity, overdue-work claim or dispatch authority.
- Reports check the exact immutable report/version, original visit/plan linkage,
  current source visit/plan revisions and recorded documentation status. Published
  and after-phase documentation/checklist marks do not verify physical completion,
  repair, warranty or customer acceptance.
- Issued scope checks the exact immutable version number, saved revision, estimate,
  job baseline and original local test-preference receipt. Neither issued scope nor
  a test preference establishes genuine contract/signature/work/financial authority.
- Recorded time checks the exact segment/job relationship, recognized kind,
  submitted flag and timestamps. Missing ends remain incomplete UNKNOWN evidence;
  work/break records do not establish future availability or paid/approved payroll.

The existing Job type has no canonical physical-completion status. This is shown
as missing evidence; no status is invented from costs, visits or checkmarks. No
private contact details, unit costs, supplier identities, payroll/workforce amounts
or source private notes are added to the allowlisted staff projection.

`readVerifiedOperatingSuggestions` reserves finite session read custody for the
canonical repository/organization/actor/jobs before awaiting the original C11 reader.
Concurrent reads, changed criteria, fresh containers and subset views cannot erase
that hold or recreate an uncertain result. This is read-custody metadata, not a new
business store, canonical command reservation or global operational lock. Source
inspection/filtering/reconciliation only use retained exact objects. Existing
Copilot/Voice/trade attempt metadata and its original one-shot holds remain unchanged;
UNKNOWN never starts/replays their preparation. A lost read acknowledgment retains
UNKNOWN with no replacement. This prototype intentionally offers one finite source
review per admitted job set and repository lifetime; criteria are selected before
that review and filters remain available afterward.

Original root/repository/model/input/gate/current eligible synthetic membership and
canonical source/attempt state are checked after the final awaited hash/child
verification, synchronously during rendering and before source/job navigation.
Copied objects confer no authority. Failed retained checks are permanently UNKNOWN;
restoring a confirmation does not restore a stale view. `openVerifiedSuggestionJob`
requires the exact previously inspected source-detail object, making source review
and explicit job navigation separate controls. No fuzzy/latest/nearest substitution.
