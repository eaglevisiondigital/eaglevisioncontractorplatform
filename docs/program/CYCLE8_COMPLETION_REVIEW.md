# Cycle 8 · customer-safe completion documentation review

The default-OFF `CompletionReview({ sources: LocalJourney, enabled?: false })`
compares the actual issued job scope with one exact published report/version using
the existing customer workflow, Property Passport and Proof of Work engines. It
adds a useful documentation checklist and immutable review summary, rather than a
second property history, search index, completion system or customer transaction.

Customers' safe scope descriptions, quantities and units remain separate from
recorded observations, recommendations and checklist marks. Every scoped line is
explicitly NOT_ESTABLISHED as a finding correspondence because no exact line-to-
finding relationship exists. Similar wording, an after-stage report, checked items
or an absent concern cannot prove a repair, physical completion, acceptance or warranty.
Missing media is UNAVAILABLE and historical completeness remains UNKNOWN.

`readCompletionReview(sources, selection, gate)` requires the same actual local
repositories/model, eligible current synthetic staff, exact property/job/issued
version and selected report/version. It strictly allowlists safe branding, property,
job scope, report identity, checklist and visible observations; internal source
fingerprints stay private to in-memory bindings. Actor identity, workforce, private
notes, amounts/costs, suppliers, payroll and margin fields do not enter the snapshot.

After three explicit documentation-review checks and a separate confirmation,
`prepareCompletionReview(view, confirmation)` calls the existing two-source Proof
of Work preparation and freezes its SHA-256-bound summary. It claims one attempt per
authoritative Operations/business-source target, excluding reviewer identity before the first await. Failed/lost outcomes cannot be retried using a
fresh source view, replacement customer model or second eligible reviewer. `reconcileCompletionReview(packet)` reads the exact retained
packet only and permanently holds UNKNOWN. `openCompletionSource(view)` re-reads
only its original report/version and focuses the exact source detail in the UI.
Original inputs, source/model instances, current membership and authorization are
rechecked after the final await. Historical packet contents remain unchanged when
later reports or access changes make the current review unavailable.
