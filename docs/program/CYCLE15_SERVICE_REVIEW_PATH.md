## Relationship evidence stays honest

The current actual IntakeRequest, Estimate and Job contracts expose no request to
estimate/job foreign key. The original C13 reader explicitly labels this association
staff-selected. This package therefore reports the absent recorded relationship as
UNKNOWN and requires **I confirm this exact job as staff-selected review context.**
It does not recognize an invented field, fabricate a positive recorded-link fixture
or infer a foreign key from customer/property labels or a selected source handle.

Separately available recorded relationships remain visible: the exact job's immutable
issued baseline and the original published report's recorded job link. Sibling or
ambiguous property documentation stays UNKNOWN for the selected job. These recorded
relationships never turn the missing request/job relationship into a recorded one.
A future genuine request/job producer requires a reviewed source contract, not an
ad-hoc presentation field or fixture. Missing linkage does not prevent separately
confirmed staff inspection of already authorized source records.

## Actual source path and return

`readServiceReviewRequests(sources, gate)` composes the original C13
`readServicePassportDesk` and groups actual request IDs with admitted job contexts.
Its available counts describe three requests/four handles in the prepared environment,
not complete CRM history. Duplicate/conflicting request/customer/property or job
identities deny. `selectServiceReviewContext(view, selectedJobId?)` independently
validates the presentation hint and never substitutes an inaccessible job.

`openServiceReviewPath(view, {request_id, job_id, staff_context_confirmed:true})`
requires an exact visible request and same authorized context. It reuses C14
`readServiceSourceContinuity`, checks request/customer/property/job/issued identity
again and retains the original customer-safe scope/Passport projection. No new
request, job, report, history, completion, verification or customer store exists.

`openServiceReviewReport(path, exactReference)` and `openServiceReviewFinding`
delegate to C14's original safe published-evidence readers. They preserve report,
published version, finding ID/source position and exact property. There is no newest,
nearest, fuzzy, unpublished or replacement-version fallback. Original report content,
checklist marks, observations and separate recommendations remain unchanged.

`returnServiceReviewRequest(path)` returns the SAME retained request view and exact
request/job selection. The UI keeps original report/finding state while returning
and **Resume retained service evidence** restores that same evidence. Changing the
request, job or explicit context confirmation withdraws old detail. **Return to
report selection** retains the same path/property, while **Open same service job …**
is a separately checked host navigation action after report inspection.

## Access, uncertainty and useful UI

DEV, explicit enablement and literal HTTP loopback admission precede source getters,
input coercion and serializers. All defaults are OFF. Strict own-data inputs and
original retained views reject copies, getters, extra fields and coercion without
execution. Current eligible membership, company/CRM availability, source root,
repository/model identity, request/customer/property/job/issued/report identity,
original context confirmation and saved revisions are checked after awaits, final
hashes, on render and before return/navigation. Late responses are discarded after
context change; foreign or withdrawn selected-job hints never fall back.

Observed uncertainty is terminal for the retained path. Restoring fields cannot
revive it, replay an action or create replacement evidence. Exact inspection remains
read-only. No command, reservation, approval, message, dispatch, financial or hosted
authority is added. Same-tab state is not genuine Auth or durable custody.

Customer-safe content excludes staff notes, internal costs/rates, suppliers,
workforce, receipt metadata, private findings and unrelated customers. Physical
completion, customer acceptance, warranty and history completeness stay UNKNOWN.
After-phase records, checkmarks, photos and absent findings never prove repair,
physical PASS, genuine approval or work/financial authority.

Scoped styles reuse current journey tokens, warm surfaces,44px controls, auto-height
headers, wrapping identities and the existing760px responsive context. Definition

Loading, OFF, no-source, denied/stale and UNKNOWN states are explicit. Main owns
actual mounted desktop/tablet/mobile, all-brand, keyboard/axe and task/return proof;
static render or source tests are not visual approval.
