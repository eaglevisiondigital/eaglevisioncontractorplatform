manufactured and no genuine customer approval is claimed. Distinct same-property
jobs retain their original receipts, issued versions and report associations.

Recorded workflow facts include actual request status, issued-source status, exact
plan/revision/cadence/timezone, and scheduled/published visit IDs, dates, revisions,

issued job/estimate/version/source hash, customer-facing scope lines and quantities,

recommendations. Staff receipt/offer/actor data, private notes, costs, suppliers,
payroll, worker information and internal financial projections never enter it.
`projectIssuedReview` remains issued-only and is unchanged.

Requirements explain the proof still needed for exact scope/quantity verification,
authorized physical completion verification, genuine customer acceptance and

those proofs are unavailable in the existing sources. This read-only requirements
projection does not create proof or grant an operational pass. Photos, recorded
checkmarks, after-phase reports and absence of findings never verify physical
completion, customer acceptance, repair or warranty. Media availability and history

Property documentation is associated with the selected job only when the existing
Passport supplies one exact recorded job link. Sibling/unlinked/ambiguous property
documentation remains UNKNOWN for that selected job. Exact original
property/report/published-version identity is retained; no fuzzy, nearest or latest
fallback exists. `openServiceLifecycleReport(detail, exactReference)` inspects the
same authorized source. `selectServiceLifecycleJob(detail)` is a separate checked
local navigation target and never executes a job or customer action.
