# NMI cross-engine synthetic acceptance

This package is an executable acceptance fixture on exact PR452 `e2414b42fcf1acc65c0d40a11d917cee8121fc04`. It composes existing payment engines and SQL; it adds no runtime, connected route, state machine, schema, provider adapter or source admission. Release 1.0 remains NO-GO.

## Execute the bounded package

```sh
node node_modules/vitest/vitest.mjs run tests/nmi-lifecycle-acceptance-source.test.ts tests/database/nmi-lifecycle-acceptance.test.ts --maxWorkers=1
```

The database test uses the existing test engine: PGlite by default; native PostgreSQL 17 through an explicitly supplied disposable local temporary Unix socket (`EV_TEST_PG_SOCKET`, port 55477, fixture owner `ev_test`). Bootstrap/migrations and synthetic role/lease/authorization provisioning apply only to that disposable test database. No operational SQL installation is authorized. Local native qualification used a private TCP-disabled cluster and stopped/removed it afterward.

The new fixture verifies literal SHA256 and regular-file modes for all consumed PR452 runtime, migration, bootstrap and original merchant/test-engine sources. Six source controls accept the exact frame and deny changed lookup, changed SQL, changed business hash helper and unavailable source, and reject runtime pin rebinding/deletion without fallback. This is test provenance, not a new production source guard or operational capability.

All keys, consent/authorization references, token references, reports, API responses and signatures are fictional trusted fixtures. The prebound token resolver implements only the existing injected vault contract; it does not collect, tokenize or persist payment methods. Database authorization reuse is independently rejected by the actual existing SQL. Native snapshots use a fresh backend after commits and verify original identities, persisted counts and absence of private provider/token/key data. Provider GET/POST ports are explicit allowlisted fakes with no network fallback.

The first draft exposed four new test-isolation failures: prior reconciliation rows survived the fixture's reset. The reset now explicitly truncates that existing disposable table; all original count assertions are retained. A nullable test `RequestInit` access was corrected for strict TypeScript. The source preflight uses builtin Node crypto and freezes expected pins, with explicit changed-helper and runtime-rebinding controls. Independent review also replaced command re-entry after a lost finish ACK with the strictly read-only transaction port; the resolver call-count assertion prevents that acceptance case from silently becoming a replay. No canonical defect or protected-source correction was needed.

## Contract boundaries and retained evidence

The official [Sale reference](https://docs.nmi.com/reference/create-sale-v5) defines a combined authorization and capture. The distinct [Authorization reference](https://docs.nmi.com/reference/create-auth-v5) uses a separate endpoint. This package deliberately makes no auth-only/capture-later or void implementation claim. A local SQL authorization is permission for the existing Sale command, not evidence of provider authorization-only processing.

Original PR452 lookup43+native5 evidence remains accepted and is not repeated. New package qualification: source6 and PGlite14 PASS/0FAIL/0SKIP and native14 PASS/0FAIL/0SKIP (exact database case bodies retained across the subsequent source-preflight-only hardening), with types, scoped lint/format and feature/design-lock checks. Independent review and exact-head hosted CI are separate evidence; local passing tests do not imply their completion.

A signed notification authenticates bytes and event identity. A successful lookup supplies configuration-bound facts. A balanced staff-supplied synthetic report compares canonical rows. None independently verifies processor fees, net funding, bank settlement, merchant-key ownership, customer payment receipt issuance or delivery. The explicit synthetic observation is a test authority fixture, not provider acceptance.
