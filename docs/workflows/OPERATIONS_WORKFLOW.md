## Functioning, unmounted source integration

`readOperationsWorkflow(repo, target, { operations, incident }, gate)` composes the
existing `reviewOperationsExperiments` and `prepareStormNetworkReview` engines over
Main's same actual Property/Phase3/CRM instances. The exact existing target contains
a non-null job, immutable issued estimate version, customer and property. The caller
provides explicit existing `OperationsExperimentInput` and `StormNetworkInput`;
no dates, proposal windows, working hours, source observations, incident conditions,
route stops, notes or scope selections are invented by the facade.

Every retained booking, route, capture and other-window work order must belong to
that same target job/customer/property/issued version. Exact visit identity must
match the retained producer card. Another tenant or same-company job is rejected,
even if wording, customer or address appears similar. The original field producer
binding is checked without executing caller getters or serializers.

The original engines remain authoritative for proposed timing, canonical overlap/
union arithmetic, explicit supplied route ordering, bounded unsaved capture notes,
manual incident priority and exact included scope references. The facade returns
those frozen prepared reviews, their original hashes and a composite content digest.
Storm and Operations references are checked against the same shared source SHA and
job. There is no second capacity engine, booking/inspection model, offline queue,
property store, partner directory, schema or ledger.

Meaningful outputs remain strictly limited:

- Booking windows and working hours are human proposals; actual availability is
  UNKNOWN, including when no recorded time conflict appears.
- Route order is explicitly supplied, with no fabricated geography, travel times
  or optimization claim.
- Capture is an unsaved session-only note, not durable synchronization, a published
  inspection, completion proof or replay token.
- Storm conditions are explicit human reports, not weather-feed observations,
  safety assessments or verified damage.
- Contractor Network content is **SOURCE REFERENCE ONLY, NOT ENDORSEMENT OR ACCESS**.
  The inherited same-tenant IDs-only sharing preview retains recipient null and
  blocked delivery; there is no discovery, cross-tenant access, export or endorsement.

The module is default OFF and requires explicit current enabled/confirmed admission.
Connected or non-PropertyRepository objects reject before operational reads. It is
unmounted: no App route, UI, network listener, provider, browser worker or new source
factory is added. Existing engine and source files remain unchanged.

Original target and complete explicit input remain live across every awaited read,
hash and child reconciliation. Descriptor-only, bounded plain-data fingerprints
reject accessors, serializers, symbols, custom prototypes and oversized graphs;
these fingerprints are ephemeral private metadata, not business records.

synchronous checkpoints revalidate exact target job/issued/customer/property/current

await follows the terminal check. Real target-job and plan changes during the final

not atomically cover all other-job entries. This existing limit is explicit:
`workforce_currentness: CAPTURED_NOT_ATOMIC`, `capacity_authority: UNVERIFIED` and
`actual_availability: UNKNOWN`. A final other-job-time race is characterized rather
than claimed fixed. All actions remain false, and subsequent exact child
reconciliation returns UNKNOWN. Current target reference equality never establishes

and composes the original exact read-only reconcilers. It returns
